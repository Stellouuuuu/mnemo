# v0.5 - Tools

**Objectif :** le modèle peut demander des outils, et le serveur décide de ce qui s'exécute.

## Checklist

- [x] Outils : calculatrice (sans `eval`), recherche dans les documents, effacement d'un souvenir
- [x] Définitions validées par un schéma (champs inconnus refusés : un modèle manipulé ne peut pas viser un autre compte)
- [x] L'identité de l'utilisateur vient de la session, jamais des arguments du modèle
- [x] Action sensible = accord explicite de l'utilisateur (écran « Autoriser / Refuser »), à usage unique, expirant au bout de 5 minutes
- [x] Journal des appels (`tool_audit`) : demandé, exécuté, refusé, confirmé, expiré
- [x] Boucle bornée (3 tours d'outils, 3 appels par tour) et résultats d'outils traités comme des données
- [x] Appel d'outil écrit en texte par le modèle retrouvé, et soumis aux mêmes règles
- [x] Tests : une consigne cachée dans un document ne peut pas effacer un souvenir
- [x] Le modèle choisit le bon outil de façon assez fiable : **non** avec `mistral` 7B (2/8), oui avec `qwen2.5:3b` (10/12 calculs, 9/9 effacements), au prix d'une résistance moindre aux injections (audit v0.5)
- [x] Audit AegisAI de la v0.5, avec les scénarios d'outils

## Hors scope v0.5

- Exécution de code, accès aux fichiers, accès réseau (aucun de ces outils n'existe : chacun demanderait son propre modèle de permissions)
- Agents multi-étapes (v0.6)
